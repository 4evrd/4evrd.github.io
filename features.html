The bouncer

One permanent connection per network, shared by every client you attach, with what you missed waiting for you.

Always connected
evrd stays on each network while no client is attached, and reconnects with jittered backoff when a link drops.
One link, many clients
irssi, WeeChat, HexChat and the web app share one upstream connection. What you send shows on your other clients too.
user/network:password
Backlog with real timestamps
Messages and channel events (joins, parts, quits, kicks, nick changes, topics, modes) are saved per channel and replayed with their original times.
backlog_lines 2000
Playback buffers
Each channel and private message has a buffer that plays back its last lines (0 to 500) when an IRC client attaches.
setbuffer <buffer|*> [lines]
Auto-clear
A buffer can play back only what arrived since an IRC client was last on that network, as ZNC's AutoClearChanBuffer does.
autoclear <buffer> on|off
Replay on demand
Play any buffer's last lines back from history, whether it was cleared or not.
playback <buffer> [lines]
Plain backlog for plain clients
A client that asks for no IRCv3 capabilities gets just the chat, with timestamps in the text, so replay never confuses its nick list.
Detached channels
Stay joined and logged, hidden from IRC clients until you /join again, then show what you missed.
detach <#chan>
Disabled channels
Leave a channel but keep it saved, key included, to join it again later.
disablechan <#chan>
Away when nobody's attached
Optionally marks you away on every network while no IRC client or web app is attached.
Account → Profile
Timestamps for older clients
Clients without server-time get the time in the replayed text, in your own strftime format and time zone.
Account → Bouncer
CTCP replies
Fixed replies of your own, or an empty one to block a request. With no client attached, evrd answers VERSION, PING and TIME itself.
Account → Bouncer

Networks and services

Every network gets its own settings page, with what ZNC offers without modules. All of it works from *status too.

Network directory
Add network offers a searchable list of public networks; picking one fills in its servers and suggested channels.
addnetwork libera · directory [search]
Several servers per network
Each with its own port, TLS and server password. evrd moves to the next one each time the link drops.
addserver <host> [[+]port] [pass]
Identity per network
Nick, alternate nick, ident, real name and quit message, falling back to your account's defaults.
set altnick · set ident · set quitmsg
Services login
SASL PLAIN, IDENTIFY to NickServ, a command of your own (Undernet's X) or QuakeNet's Q, with presets for common networks.
set auth auto|sasl|nickserv|command|none
Nick recovery
When your nick is taken, evrd logs in on the alternate, asks services to GHOST, REGAIN or RECOVER it, and switches back.
set ghost ghost|regain|recover|off
Join after identifying
Holds channel joins until services confirm the login, so registered-only channels let you in.
set joinafterauth on · set authtimeout 15
Certificate trust
System CAs, trust everything, or pinned SHA-256 fingerprints. A refused certificate's fingerprint comes with a button to trust it.
trustpki · trustallcerts · addfingerprint
Encodings
For networks that aren't UTF-8: decode only invalid UTF-8, or decode and send in a charset.
set encoding <charset>
Flood protection
Lines per second and burst towards the network, and a delay before joining channels.
floodrate · floodburst · joindelay
Connection log
Each network's page says why it can't connect, what services answered, and what to do about it.

Coming from ZNC

The commands, setting names and modules you already know carry over.

*status from any client
Add, connect and remove networks; manage servers, fingerprints, channels, buffers and bind hosts without leaving your client.
/msg *status help
ZNC's command names
ListNetworks, JumpNetwork, AddNetwork, AddTrustedServerFingerprint and the rest of ZNC's *status names work, case-insensitive.
The /znc command
ZNC's raw command is the same as messaging *status, from IRC clients and the web chat.
/znc ListNetworks · /quote znc …
Switch networks in place
Move an attached client to another network without reconnecting it.
jumpnetwork <network>
Import ZNC logs
Loads a ZNC user's log module files into evrd's history, so old conversations come along.
evrctl history import-znc <user> <znc-user-dir>
ZNC's modules
perform, keepnick, kickrejoin, autocycle, autoop, autovoice, alias, ctcpflood and q, switched on per network.
loadmod · unloadmod · modset

IRCv3

A client that asks for nothing gets plain IRC. One that asks gets evrd's own capabilities on every network, and the network's while its link has them. Clients without a capability get its lines translated or left out. The full table.

evrd's own

Scrollback on demand
Clients page through history with LATEST, BEFORE, AFTER, AROUND, BETWEEN and TARGETS, by msgid or timestamp, up to 1,000 lines a request.
draft/chathistory
Events in history
Replayed and fetched history carries JOIN, PART, QUIT, KICK, NICK, TOPIC and MODE as real lines.
draft/event-playback
Read markers
How far each buffer is read is shared with your other clients and the web app within a few seconds.
draft/read-marker
Networks from the client
Goguma and gamja list, add, change and remove your networks, with one connection per network.
soju.im/bouncer-networks · soju.im/bouncer-networks-notify
Batched, tagged backlog
Each buffer's backlog in its own batch, with original @time and a stable @msgid.
batch · server-time · message-tags
Your own lines echoed
With the same msgid they have in history.
echo-message
SASL to evrd
Sign in with SASL PLAIN instead of a server password; user/network picks the network.
sasl=PLAIN
TLS only
Clients are told to keep to TLS, offered only with a certificate they trust.
sts · irc_sts 24h
The rest
Capability changes as they happen, standard replies, NAMES only when asked, and AWAY sent during registration.
cap-notify · standard-replies · no-implicit-names · draft/pre-away

Passed through from the network

Labeled responses
Offered while the network has it; each labeled reply goes back to the client that sent the command.
labeled-response
Multiline messages
With the network's limits, sent as one batch and saved a line at a time.
draft/multiline
Typing, replies and reactions
Client-only tags pass both ways, and your typing shows on your other clients. TAGMSG lines are never saved.
+typing · +draft/reply · +draft/react
Network capabilities
Requested from the network when it offers them and passed through to the clients that ask.
multi-prefix · userhost-in-names · extended-join · account-notify · account-tag · away-notify · chghost · invite-notify · setname · draft/channel-rename · draft/message-redaction · extended-monitor
ISUPPORT, MONITOR and bots
The network's 005 tokens, one MONITOR list per network shared by your clients, and bot mode with the @bot tag.
PREFIX · CHANTYPES · MONITOR · BOT

Staying connected

Restarts, upgrades and refusing servers don't take anyone off IRC, and large networks see well-behaved connections.

Connection holder
evrd-links holds every network connection while evrd restarts, answers the servers' pings and buffers what arrives. The next evrd takes each one back without registering or rejoining.
links_socket
IRC clients held too
The holder keeps the IRC listeners, so a restart is invisible to attached clients: no disconnect, no second welcome.
hold_clients yes
The gap lands in history
What the networks said while evrd was away is replayed into history with its real time.
evrd-links -buffer (4 MB per network)
Polite to refusing servers
No reconnect loop after a ban or kill. A server that refuses this address rests 30 minutes, doubling to 4 hours, while the network's others are tried.
Connect pacing
New connections to one server host are spaced out per node, so a failover or netsplit recovery reconnects users gradually.
connect_rate 5
Source addresses
Spread users over several local addresses, each user always on the same one.
upstream_bind
An IPv6 address per user
Each user connects from a stable address of their own out of a routed prefix (Linux).
upstream_prefix6 2001:db8:42::/64
Bind hosts
Users pick an address to connect from, for their account or one network. Admins can use any address and lock a user's choice. IPv6 bind hosts need no per-address interface setup on Linux.
bindhost · setbindhost
IPv6 first
Connects to IRC servers over IPv6 first and falls back to IPv4, or the other way round.
prefer_ipv6 yes
Ident
A built-in identd answers with each network's ident, or evrd keeps an oidentd file up to date.
identd_listen :113 · ident_file

Sign-in and security

Passwords, single sign-on, or both, for the web app and for IRC clients.

Passwords
At least 10 characters, stored as bcrypt hashes. A password an admin sets is temporary: the user picks their own at next sign-in.
password_login yes
Single sign-on
OpenID Connect with any provider (Logto, authentik, Keycloak…). Accounts are created on first sign-in, and a provider role can make an admin.
oidc_issuer · oidc_admin_role · oidc_roles_claim
IRC client passwords
One per device, made on the IRC clients page and revoked one at a time.
Sign in by link
Connect without a password and *status sends a one-time link. Allow the client on the website, through your identity provider and its MFA.
irc_link_signin yes
Remembered devices
Allowing a client by link can remember it, listed and revocable on the IRC clients page.
irc_remember_days 30
SSO password in IRC clients
Checked with the provider's password grant, an LDAP bind as the user, or Logto's Management API. A right password is remembered for 10 minutes.
sso_irc_password password_grant|ldap|logto
Second factor for IRC
An authenticator app code after the password, or /msg *status otp, with ten one-time recovery codes. Each user's choice, or required by the admin.
irc_mfa off|optional|required
Lockout
Ten wrong passwords within 15 minutes, over IRC or on the web, lock the account out for a while.
Sessions you can see
Web sessions live in the database behind an HttpOnly cookie, survive restarts, and can be signed out from the Account page.
session_ttl 720h
Allowed addresses
Each account can limit the addresses it may sign in from, on the web and over IRC.
Account → Bouncer
Encrypted secrets
Network passwords, services commands, module settings, secret settings and certificate keys are AES-256-GCM encrypted under a key kept outside the database, and the key can be rotated.
secret_key · secret_key_old
Certificates
Let's Encrypt (got and renewed by evrd), self-signed, or your own files, re-read when they change or on SIGHUP. Switchable while evrd runs.
tls acme|selfsigned|files
Trusted proxies only
X-Forwarded-For is believed only from the proxies you list.
trusted_proxies
Strict Content-Security-Policy
The web app has no inline scripts, so script-src 'self' doesn't break it.
Confinement
Started as root, evrd binds its ports, then chroots and drops to its own user. On OpenBSD it also unveils only its data and pledges away exec.
chroot · user

Hosting others

What an admin needs to run evrd for a community: accounts, limits and settings, from the web app or a shell.

Roles
Every account is a user or an admin. The last active admin can't be demoted, suspended or deleted.
evrctl user role <name> user|admin
Per-user limits
Networks, attached IRC clients and backlog lines, with server defaults and per-user overrides.
max_networks · max_clients · backlog_lines
Suspension
Signs a user out everywhere, drops their IRC clients and disconnects their networks. Lifting it reconnects them.
evrctl user suspend <name> [reason]
Password resets
Reset gives a one-time password; the user picks their own at next sign-in.
Settings from the web app
Admin → Settings edits most of evrd.conf, shows where each value comes from, and applies most of them live on every node.
settings_write_conf
Admin overview
Totals across every user and node, what needs attention, and the versions of evrd and the connection holder.
A page per user
Their networks, why one can't connect, its health and its connection log.
Provisioning API
Create accounts and their networks before the owner signs in, for migrating users from another bouncer. Repeatable; the first matching SSO sign-in claims the account.
provision_token
Your own network list
Offer evrd.sh's directory, a file of your own (private networks included), or none.
network_directory
evrctl
Accounts, secret keys and history from a shell, with the same config as evrd.
evrctl user · genkey · history

Languages

The web app and evrd's own words, in each user's language. Anyone can add a language or change some of the text without touching the code.

Seven built in
English, Deutsch, Español, Italiano, Bahasa Indonesia, 日本語 and Türkçe.
evrd's own words
*status replies and help, connection logs, errors and the activity feed follow each user's language.
Account → Profile → Language
Logs in the reader's language
Connection logs and events keep what evrd said, not the sentence, so an admin reads a user's log in their own language.
Upload a translation
Admins for everyone, any user for themselves; a partial one falls back to the built-in text, then English.
Admin → Settings → Languages
Five file formats
JSON, CSV, gettext PO (Poedit), XLIFF 1.2 and 2.0, and YAML, with templates and current languages to download.
.json · .csv · .po · .pot · .xlf · .yaml
Checked before saving
Placeholders must match English, plurals follow CLDR categories, and the upload shows what's still untranslated.

Modules

Optional behaviours you switch on per network, like ZNC's network modules. Changes apply when you save, without reconnecting.

perform
Sends your commands every time evrd signs in to the network, with %nick% filled in.
modset perform commands /mode %nick% +i
keepnick
Wins your nick back as soon as it's free, trying every 30 seconds meanwhile.
kickrejoin
Rejoins a channel you were kicked from, after a delay.
modset kickrejoin delay 10
autocycle
Leaves and rejoins a channel where you're alone without ops, so you get them.
autoop, autovoice
Gives ops or voice to the masks you list when they join a channel where you have ops.
alias
Your own commands for IRC clients, with %1, %1+ and %nick%.
name = commands
ctcpflood
Stops answering and passing on CTCP requests while too many arrive at once.
q
Logs in to QuakeNet's Q and hides your host. The QuakeNet preset switches it on.
From any client
Switch modules on and set them up on the network's page or from *status. Their settings are stored encrypted.
modules · loadmod · unloadmod · modset
Off for everyone
Admins can switch modules off server-wide.
modules_off autoop autovoice

Clustering and metrics

The same binary runs as a single node on SQLite and Pebble, or as a cluster against Postgres and ScyllaDB.

Several nodes
Any number of nodes behind a plain round-robin load balancer. Each user is owned by one node; the others forward their IRC and web traffic to it.
node_id · internal_listen · cluster_secret
Failover
When a node dies its users move to the others once their leases run out, about 20 seconds by default.
cluster_lease 20s
Rolling deploys
A node stopped with SIGTERM hands its users over at once instead of waiting for its leases to expire.
No message bus
IRC clients are spliced to the owner node and web requests reverse-proxied to it; nothing else crosses nodes.
Storage
SQLite or Postgres for accounts and settings; embedded Pebble or ScyllaDB for chat history.
db sqlite:|postgres:// · history pebble:|scylla://
Copy history between stores
Move chat history from one store to another, for example when a single node grows into a cluster.
evrctl history copy <from> <to>
OpenTelemetry metrics
Lines per network, link state, lag, disconnects, attached clients, web streams, users per node and more, over OTLP/HTTP.
otel_endpoint · otel_interval 15s
Charts from VictoriaMetrics
The web app reads metrics back for its traffic charts and health pages; without a store the charts say metrics are off.
metrics_url
Traces
Spans for web API requests and the services behind them, to any OTLP/HTTP collector.
otel_traces_endpoint
Admin → Metrics
Every metric evrd exports, charted for admins.
Grafana dashboard
A ready-made dashboard: traffic, upstream links and lag, clients, sign-ins, users per node and the versions running.
deploy/grafana/evrd.json

Deployment

Every install method runs the same binary.

Container images
The daemon with evrctl, and the web app on nginx, for amd64 and arm64, with a Compose file and an optional metrics profile.
ghcr.io/4evrd/evrd · ghcr.io/4evrd/evrd-web
OpenBSD installer
One script installs evrd as a confined daemon with Let's Encrypt, optional SSO and the connection holder. -y runs it without questions.
ftp -o - …/install.sh | sh
Release archives
Linux, FreeBSD, macOS and OpenBSD, amd64 and arm64, each with evrd, evrctl and the built web app, checked against a SHA256 file.
No database server needed
A single node runs on SQLite and an embedded Pebble history store.
db sqlite:… · history pebble:…
HTTPS without a proxy
evrd can serve the web app over HTTPS itself and redirect plain HTTP, or sit behind nginx, Caddy, Traefik or relayd.
https_listen :443 · http_listen :80 · web_root
Upgrades in place
Database changes apply at startup. Images are tagged per release; pin one or follow latest.
EVRD_VERSION
Restarts only when needed
Re-running the OpenBSD installer restarts evrd only if its program changed, and the holder only when it must.
Environment overrides
Startup settings and secrets can come from the environment, which wins over the file.
EVRD_CONFIG · EVRD_DB · EVRD_HISTORY · EVRD_SECRET_KEY
Build from source
Pure Go with no cgo, and a Svelte web app built with pnpm.
CGO_ENABLED=0 go build ./cmd/evrd ./cmd/evrctl

Try it on one machine first.

A single node needs no database server. Install it, create an admin with evrctl user add -admin, and add a network.
