The bouncer

One permanent connection per network, shared by every client you attach, with what you missed waiting for you.

  • Always connectedevrd stays on each network while no client is attached, and reconnects with jittered backoff when a link drops.

    A link that drops after working for a while reconnects at once; one cut off soon after connecting backs off, up to five minutes. Switching a network off in the web app or with disconnect is the only thing that takes it down for good.

    Full docs
  • One link, many clientsirssi, WeeChat, HexChat and the web app share one upstream connection. What you send shows on your other clients too.user/network:password

    Clients attach with a server password of user:password (your first network) or user/network:password. Your own messages, notices and /me actions are saved and shown on your other clients and in the web chat. max_clients caps how many IRC clients a user can attach at once (0, the default, is unlimited).

    Full docs
  • Backlog with real timestampsMessages and channel events are saved per channel and replayed with their original times.backlog_lines 2000

    Joins, parts, quits, kicks, nick changes, topics and modes are saved with the messages. evrd keeps backlog_lines per channel or private message (2,000 by default, 0 keeps everything) and prunes every 10 minutes. Clients with server-time get each line tagged @time.

    Full docs
  • Playback buffersEach channel and private message has a buffer that plays back its last lines (0 to 500) when an IRC client attaches.setbuffer <buffer|*> [lines]

    Set the default under Account → Bouncer, per network with setbuffer * <lines>, or for one buffer. The network's page in the web app has the same settings under Playback, with what's waiting in each buffer. Buffer names take wildcards (#evrd*) and lists (#a,#b).

    Full docs
  • Auto-clearA buffer can play back only what arrived since an IRC client was last on that network.autoclear <buffer> on|off|-

    Like ZNC's AutoClearChanBuffer and AutoClearQueryBuffer: set it for channels and for private messages under Account → Bouncer, or per buffer. While another client is on the network, an auto-clearing buffer plays back nothing. clearbuffer starts a buffer over; the lines stay in history.

    Full docs
  • Replay on demandPlay any buffer's last lines back from history, whether it was cleared or not.playback <buffer> [lines]

    playbuffer <buffer> plays a buffer back as it would on attach; playback <buffer> [lines] replays its last lines from history (up to 500).

    Full docs
  • Plain backlog for plain clientsA client that asks for no IRCv3 capabilities gets just the chat, with timestamps in the text.

    Channel events are replayed only to clients that ask for draft/event-playback, as real lines in a history batch, so replay never confuses a plain client's nick list. The backlog's line count counts only what's replayed.

    Full docs
  • Detached channelsStay joined and logged, hidden from IRC clients until you /join again, then show what you missed.detach <#chan>

    Detach from *status, with /detach #chan from a client, or on the network's Channels settings. attach <#chan> or /join brings the channel back with its backlog.

    Full docs
  • Disabled channelsLeave a channel but keep it saved, key included, to join it again later.disablechan <#chan>

    enablechan <#chan> joins it again. channels lists the network's saved channels and showchan <#chan> one channel's state, settings and buffer.

    Full docs
  • Away when nobody's attachedOptionally marks you away on every network while no IRC client or web app is attached.Account → Profile

    Turn on "Mark me away when no client is attached". evrd sets you back when a client or the web app attaches. A client with draft/pre-away can leave it to auto-away by sending AWAY * while registering.

    Full docs
  • Timestamps for older clientsClients without server-time get the time in the replayed text, in your own format and time zone.Account → Bouncer

    Prepended or appended, as [12:34:56] hello, with a strftime format and a time zone of your choice.

    Full docs
  • CTCP repliesFixed replies of your own, or an empty one to block a request. With no client attached, evrd answers VERSION, PING and TIME itself.Account → Bouncer

    Set per account under Account → Bouncer. The ctcpflood module adds flood protection on top.

    Full docs

Networks and services

Every network gets its own settings page, with what ZNC offers without modules. All of it works from *status too.

  • Network directoryAdd network offers a searchable list of public networks; picking one fills in its servers and suggested channels.addnetwork libera · directory [search]

    Only the nickname is left to type. evrd fetches the list from evrd.sh at startup and every 12 hours and keeps the last good copy in its database; admins can point network_directory at a file of their own or turn it off.

    Full docs
  • Several servers per networkEach with its own port, TLS and server password. evrd moves to the next one each time the link drops.addserver <host> [[+]port] [pass]

    listservers shows them in order, delserver <host> [port] removes one, and jump [server] reconnects to the next server or a named one. +port means TLS (default +6697).

    Full docs
  • Identity per networkNick, alternate nick, ident, real name and quit message, falling back to your account's defaults.set altnick · set ident · set quitmsg

    Empty fields use the defaults under Account → Profile and Account → Bouncer. The bind host is set the same way, per network or for the whole account.

    Full docs
  • Services loginSASL PLAIN, IDENTIFY to NickServ, a command of your own (Undernet's X) or QuakeNet's Q, with presets for common networks.set auth auto|sasl|nickserv|command|none

    Automatic (the default) uses SASL PLAIN when the network offers it, otherwise PASS and IDENTIFY. Presets cover Atheme and Anope, DALnet, Undernet's X and QuakeNet's Q. The password is stored encrypted and never sent back to the browser. SASL EXTERNAL isn't offered.

    Full docs
  • Nick recoveryWhen your nick is taken, evrd logs in on the alternate, asks services to GHOST, REGAIN or RECOVER it, and switches back.set ghost ghost|regain|recover|off

    With "IDENTIFY sends: just the password" (older services that identify you to the nick in use), it frees the nick first and identifies once it's back.

    Full docs
  • Join after identifyingHolds channel joins until services confirm the login, so registered-only channels let you in.set joinafterauth on · set authtimeout 15

    For channels with +r or +R. If services don't answer within the wait (15 seconds by default), evrd joins anyway. The connection log says what services answered.

    Full docs
  • Certificate trustSystem CAs, trust everything, or pinned SHA-256 fingerprints.trustpki · trustallcerts · addfingerprint

    TrustPKI verifies against the system CAs; TrustAllCerts accepts any certificate; fingerprints pin specific ones. When a certificate is refused, the network page shows its fingerprint with a button to trust it.

    Full docs
  • EncodingsFor networks that aren't UTF-8: decode only invalid UTF-8, or decode and send in a charset.set encoding <charset>

    ^charset decodes only lines that aren't valid UTF-8; charset decodes and sends everything in it.

    Full docs
  • Flood protectionLines per second and burst towards the network, and a delay before joining channels.floodrate · floodburst · joindelay

    Set on the network's Advanced settings or with *status set. - clears a setting back to its default.

    Full docs
  • Connection logEach network's page says why it can't connect, what services answered, and what to do about it.

    Timeouts, refusals, unknown hosts, TLS and certificate problems and services replies are logged in plain words, in your own language. The Reconnects page lists which networks reconnected in the last day and why.

    Full docs

Coming from ZNC

The commands, setting names and modules you already know carry over.

  • *status from any clientAdd, connect and remove networks; manage servers, fingerprints, channels, buffers and bind hosts without leaving your client./msg *status help

    help lists every command as a table. *status answers in your account's language; command names stay the same in every language. The web chat runs *status commands too, with /status help.

    Full docs
  • ZNC's command namesListNetworks, JumpNetwork, AddNetwork, AddTrustedServerFingerprint and the rest of ZNC's names work.

    Commands are case-insensitive. ZNC's buffer commands (ClearBuffer, ClearAllChannelBuffers, PlayBuffer, SetBuffer), channel commands (Attach, Detach, EnableChan, DisableChan) and bind host commands carry the same names.

    Full docs
  • The /znc commandZNC's raw command is the same as messaging *status, from IRC clients and the web chat./znc ListNetworks · /quote znc …

    /znc ListNetworks and /quote znc ListNetworks both run ListNetworks as if sent to *status.

    Full docs
  • Switch networks in placeMove an attached client to another network without reconnecting it.jumpnetwork <network>

    A client with cap-notify hears which capabilities changed with the network.

    Full docs
  • Import ZNC logsLoads a ZNC user's log module files into evrd's history, so old conversations come along.evrctl history import-znc <user> <znc-user-dir>

    It reads ZNC's per-user and per-network log layouts into the evrd user's networks of the same names. -dry-run counts what would be imported; -tz is the time zone ZNC wrote its logs in (UTC by default). With a Pebble store, stop evrd first, and run it once.

    Full docs
  • ZNC's modulesperform, keepnick, kickrejoin, autocycle, autoop, autovoice, alias, ctcpflood and q, switched on per network.loadmod · unloadmod · modset

    Same names as ZNC's network modules. NickServ and SASL login, saving channels, away, playback and logs aren't modules: evrd does them itself.

IRCv3

A client that asks for nothing gets plain IRC. One that asks gets evrd's own capabilities on every network, and the network's while its link has them. Clients without a capability get its lines translated or left out.

evrd's own

  • Scrollback on demandClients page through history by msgid or timestamp, up to 1,000 lines a request.draft/chathistory

    CHATHISTORY LATEST, BEFORE, AFTER, AROUND, BETWEEN and TARGETS (buffers with news since the client was last here). Clients that negotiate it get CHATHISTORY=1000 MSGREFTYPES=msgid,timestamp and no backlog on attach: they fetch what they want.

    Full docs
  • Events in historyReplayed and fetched history carries JOIN, PART, QUIT, KICK, NICK, TOPIC and MODE as real lines.draft/event-playback

    Without it, only messages, notices and actions come back. Events carry the nick only (nick!nick@network); AWAY, ACCOUNT, CHGHOST and SETNAME aren't kept in history.

    Full docs
  • Read markersHow far each buffer is read is shared with your other clients and the web app within a few seconds.draft/read-marker

    MARKREAD reads and moves the marker; it only moves forward. A client gets a channel's marker after its JOIN.

    Full docs
  • Networks from the clientGoguma and gamja list, add, change and remove your networks, with one connection per network.soju.im/bouncer-networks · soju.im/bouncer-networks-notify

    BOUNCER LISTNETWORKS, ADDNETWORK, CHANGENETWORK and DELNETWORK with soju's attributes, within your network limit. A client opens one connection per network with BOUNCER BIND <id>; each counts against your client limit. With -notify it hears when networks come, change and go.

    Full docs
  • Batched, tagged backlogEach buffer's backlog in its own batch, with original @time and a stable @msgid.batch · server-time · message-tags

    With batch, each buffer's backlog comes in BATCH +ref chathistory <buffer>. With message-tags, every saved line carries the same @msgid it has in history, so a client can drop a line it fetched twice.

    Full docs
  • Your own lines echoedWith the same msgid they have in history.echo-message

    Without it, evrd sends your own lines to your other clients only.

    Full docs
  • SASL to evrdSign in with SASL PLAIN instead of a server password; user/network picks the network.sasl=PLAIN

    Use the account password or an IRC client password. Accounts that sign in with SSO need a client password (or sign in by link), as with PASS.

    Full docs
  • TLS onlyClients are told to keep to TLS, offered only with a certificate they trust.sts · irc_sts 24h

    Needs an ircs:// listener and a certificate clients trust for irc_host (Let's Encrypt or a public CA, never self-signed). evrd checks the certificate every few minutes and stops offering sts when it isn't trusted. Set irc_sts off and wait out the duration before removing TLS.

    Full docs
  • The restCapability changes as they happen, standard replies, NAMES only when asked, and AWAY sent during registration.cap-notify · standard-replies · no-implicit-names · draft/pre-away

    CAP NEW and CAP DEL arrive when the link gains or loses a capability or the client jumps networks. Clients without standard-replies get the network's FAIL, WARN and NOTE as notices.

    Full docs

    What evrd answers itself (*status, CHATHISTORY, BOUNCER, MARKREAD, echoes) it labels; other commands go to the network with the label. Your other clients get the same lines without it. Needs batch.

    Clients without one get the old form: the highest prefix only, plain JOINs, QUIT then JOIN for chghost, PART then JOIN for a channel rename.

Staying connected

Restarts, upgrades and refusing servers don't take anyone off IRC, and large networks see well-behaved connections.

  • Connection holderevrd-links holds every network connection while evrd restarts, so nobody leaves IRC.links_socket

    evrd opens each connection and hands the socket to the holder, which does TLS and passes lines both ways. While evrd is away the holder answers the servers' pings and buffers what arrives; the next evrd takes each one back without registering or joining again. For a single node; a cluster moves users between nodes instead.

    Full docs
  • IRC clients held tooThe holder keeps the IRC listeners, so a restart is invisible to attached clients: no disconnect, no second welcome.hold_clients yes

    While evrd is away the holder answers clients' pings and keeps what they send (64 KiB each). A client evrd isn't back for within 2 minutes is told to reconnect. hold_clients no turns it off.

    Full docs
  • The gap lands in historyWhat the networks said while evrd was away is replayed into history with its real time.evrd-links -buffer

    The holder buffers up to 4 MB per network by default. Switching a network off, or deleting it, still quits it.

    Full docs
  • Polite to refusing serversNo reconnect loop after a ban or kill, and refusing servers are rested while others are tried.

    A server that refuses this address (a K-line, "banned", "not authorised") rests for 30 minutes, doubling to 4 hours while it keeps refusing; one that says you reconnect too fast rests 2 minutes. Only when every server is resting does evrd wait.

    Full docs
  • Connect pacingNew connections to one server host are spaced out per node, so a failover or netsplit recovery reconnects users gradually.connect_rate 5

    At most connect_rate new connections per second to one server host, per node (5 by default), with jittered reconnect backoff.

    Full docs
  • Source addressesSpread users over several local addresses, each user always on the same one.upstream_bind 192.0.2.10 192.0.2.11

    Per node, from the file or EVRD_UPSTREAM_BIND. Large networks cap connections per source address; this keeps users under the cap.

    Full docs
  • An IPv6 address per userEach user connects from a stable address of their own out of a routed prefix.upstream_prefix6 2001:db8:42::/64

    Needs Linux and a local route for the prefix: ip -6 route add local 2001:db8:42::/64 dev lo. Used for IPv6 servers.

    Full docs
  • Bind hostsUsers pick an address to connect from, for their account or one network.bindhost · setbindhost

    bindhost (repeatable) lists the addresses users may pick, like ZNC's BindHost. Admins can use any address and lock a user's choice. On Linux an IPv6 bind host can come from a routed prefix with only a local route: evrd binds it with IPV6_FREEBIND.

    Full docs
  • IPv6 firstConnects to IRC servers over IPv6 first and falls back to IPv4, or the other way round.prefer_ipv6 yes

    prefer_ipv6 no tries IPv4 first. With only IPv4 upstream_bind addresses, IPv4 goes first either way. Editable in Admin → Settings.

    Full docs
  • IdentA built-in identd answers with each network's ident, or evrd keeps an oidentd file up to date.identd_listen :113 · ident_file

    evrd matches each query to the connection by address and ports, even when NAT changed its port, and answers NO-USER rather than guess. In Docker, listen on a high port and map 113 to it.

    Full docs

Sign-in and security

Passwords, single sign-on, or both, for the web app and for IRC clients.

  • PasswordsAt least 10 characters, stored as bcrypt hashes.password_login yes

    A password an admin sets, or the one-time password Reset generates, is temporary: the user picks their own at next sign-in. password_login no leaves only single sign-on, and Admin → Settings refuses it until SSO is set up.

    Full docs
  • Single sign-onOpenID Connect with any provider (Logto, authentik, Keycloak…). Accounts are created on first sign-in.oidc_issuer · oidc_admin_role · oidc_roles_claim

    Code flow with PKCE as a confidential web app, redirect URI <public_url>/auth/callback, ID tokens signed with an asymmetric key. oidc_admin_role makes holders of a provider role admins; oidc_roles_claim says where the roles are (roles, groups, realm_access.roles…).

    Full docs
  • IRC client passwordsOne per device, made on the IRC clients page and revoked one at a time.

    Random, per device and revocable, so they don't need a second factor unless the admin sets irc_mfa_client_passwords yes. The page has copy-paste setup for HexChat, irssi and WeeChat.

    Full docs
  • Sign in by linkConnect without a password and *status sends a one-time link to allow the client on the website.irc_link_signin yes

    Sign in on the website the usual way (your identity provider and its MFA included), check the client's nick, network, address and time, and Allow it. The link works once, for 5 minutes. At most three links are open per address and five per account. Needs public_url.

    Full docs
  • Remembered devicesAllowing a client by link can remember it, listed and revocable on the IRC clients page.irc_remember_days 30

    Either with a new IRC client password shown once, or with the long password (24 characters or more) the client sent, so from then on it signs in by itself.

    Full docs
  • SSO password in IRC clientsChecked with the provider's password grant, an LDAP bind as the user, or Logto's Management API.sso_irc_password password_grant|ldap|logto

    Off by default. A right password is remembered for 10 minutes (a keyed hash, in memory). If the provider can't be reached the sign-in is refused, never let through, and client passwords keep working. A local account is never sent to the provider.

    Full docs
  • Second factor for IRCAn authenticator app code with the password, each user's choice or required by the admin.irc_mfa off|optional|required

    Send the code after the password (user/network:password:123456) or with /msg *status otp <code>. Ten one-time recovery codes come with the app. A client has two minutes and five tries. Set up on Account → Security.

    Full docs
  • LockoutTen wrong passwords within 15 minutes, over IRC or on the web, lock the account out for a while.

    Refused IRC sign-ins are logged as irc sign-in failed with the user, network, client address and reason, never the password.

    Full docs
  • Sessions you can seeWeb sessions live in the database behind an HttpOnly cookie, survive restarts, and can be signed out from the Account page.session_ttl 720h

    Account → Sessions lists where you're signed in and signs out other sessions. cookie_secure yes keeps the cookie HTTPS-only.

    Full docs
  • Allowed addressesEach account can limit the addresses it may sign in from, on the web and over IRC.Account → Bouncer

    Checked against the connection's own address, or X-Forwarded-For from a trusted proxy.

    Full docs
  • Encrypted secretsSaved passwords and secrets are encrypted with AES-256-GCM under a key kept outside the database.secret_key · secret_key_old

    Network passwords, services login commands, module settings, secrets set in Admin → Settings and certificate keys. evrctl genkey makes a key; to rotate, move the old one to secret_key_old and restart.

    Full docs
  • CertificatesLet's Encrypt (got and renewed by evrd), self-signed, or your own files.tls acme|selfsigned|files

    Let's Encrypt certificates renew 30 days before expiry. Files are re-read when they change and on SIGHUP, without a restart. Switchable in Admin → Settings → HTTPS & TLS while evrd runs; every cluster node serves the same certificates from the database.

    Full docs
  • Trusted proxies onlyX-Forwarded-For is believed only from the proxies you list.trusted_proxies

    Addresses or CIDR ranges, from the file or environment; the local host by default. Set it to the proxy's network when the proxy is on another machine (for example 172.16.0.0/12 in Docker).

    Full docs
  • Strict Content-Security-PolicyThe web app has no inline scripts, so script-src 'self' doesn't break it.

    A proxy can set a strict policy on every site; the app only needs connect-src 'self' for its API and WebSocket.

    Full docs
  • ConfinementStarted as root, evrd binds its ports, then chroots and drops to its own user.chroot · user

    On OpenBSD it also unveils only its data, the web app and name resolution, and pledges stdio rpath wpath cpath fattr flock inet dns (plus unix sendfd with the holder): no exec, no other files.

Modules

Optional behaviours you switch on per network, like ZNC's network modules. Changes apply when you save, without reconnecting.

  • performSends your commands every time evrd signs in to the network.modset perform commands /mode %nick% +i

    One command per line, as typed in a client (/msg …) or raw IRC; %nick% is your nick. Over *status, | separates lines. New commands run at the next sign-in.

    Full docs
  • keepnickWins your nick back as soon as it's free, trying every 30 seconds meanwhile.

    No settings.

    Full docs
  • kickrejoinRejoins a channel you were kicked from, after a delay.modset kickrejoin delay 10

    Delay in seconds, 10 by default.

    Full docs
  • autocycleLeaves and rejoins a channel where you're alone without ops, so you get them.channels *

    Channel patterns with * and ?, one per line; ! leaves one out. All channels by default.

    One per line: a nick!user@host mask (or a nick), then optionally the channels, comma-separated, wildcards allowed.

    With %1, %2… (%1+ for the rest) and %nick%; several commands separated by ;.

Clustering and metrics

The same binary runs as a single node on SQLite and Pebble, or as a cluster against Postgres and ScyllaDB.

  • Several nodesAny number of nodes behind a plain round-robin load balancer. Each user is owned by one node; the others forward to it.node_id · internal_listen · cluster_secret

    TCP passthrough for IRC and HTTP with WebSocket upgrades for the API. Ownership is a lease in Postgres placed by rendezvous hashing, so adding a node moves only a share of users. Tested load balancer configs for nginx and Traefik 3.7+.

    Full docs
  • FailoverWhen a node dies its users move to the others once their leases run out, about 20 seconds by default.cluster_lease 20s

    A node that can't renew its leases stops its users' connections first, so two nodes never hold the same nick. Users see their networks reconnect; a TCP connection can't move between machines.

    Full docs
  • Rolling deploysA node stopped with SIGTERM hands its users over at once instead of waiting for its leases to expire.

    The others pick them up on their next tick, within 5 seconds.

    Full docs
  • No message busIRC clients are spliced to the owner node and web requests reverse-proxied to it.

    Internal IRC and HTTP ports stay on a private network, authenticated with the cluster secret.

    Full docs
  • StorageSQLite or Postgres for accounts and settings; embedded Pebble or ScyllaDB for chat history.db · history

    History never goes in Postgres. ScyllaDB is shared by every node, with queued writes so a slow database doesn't stall IRC.

    Full docs
  • Copy history between storesMove chat history from one store to another, for example when a single node grows into a cluster.evrctl history copy <from> <to>

    Stop evrd first when copying from Pebble.

    Full docs
  • OpenTelemetry metricsLines per network, link state, lag, disconnects, attached clients, web streams, users per node and more.otel_endpoint · otel_interval 15s

    Over OTLP/HTTP. With VictoriaMetrics' -opentelemetry.usePrometheusNaming they come out as evrd_irc_lines_total, evrd_upstream_up, evrd_upstream_lag_seconds and friends.

    Full docs
  • Charts from VictoriaMetricsThe web app reads metrics back for its traffic charts and health pages.metrics_url

    Credentials in the URL are sent as basic auth, and Admin → Settings shows the password masked.

    Full docs
  • TracesSpans for web API requests and the services behind them, to any OTLP/HTTP collector.otel_traces_endpoint

    For example http://jaeger:4318/v1/traces.

    Full docs
  • Admin → MetricsEvery metric evrd exports, charted for admins.

    Needs metrics_url.

    Full docs
  • Grafana dashboardTraffic, upstream links and lag, clients, sign-ins, users per node and the versions running.deploy/grafana/evrd.json

    For a VictoriaMetrics or Prometheus data source with uid victoriametrics; change it on import.

Deployment

Every install method runs the same binary.

  • Container imagesThe daemon with evrctl, and the web app on nginx, for amd64 and arm64.ghcr.io/4evrd/evrd · ghcr.io/4evrd/evrd-web

    The Compose setup runs evrd, the web app and Postgres, with an optional metrics profile for VictoriaMetrics. No registry login needed.

    Full docs
  • OpenBSD installerOne script installs evrd as a confined daemon with Let's Encrypt, optional SSO and the connection holder.ftp -o - …/install.sh | sh

    It checks the release against its SHA256 file and asks for host names, certificate, who serves HTTPS and the first admin. -y runs it without questions; running it again upgrades in place.

    Full docs
  • Release archivesLinux, FreeBSD, macOS and OpenBSD, amd64 and arm64.evrd · evrctl · web/

    Each archive has evrd, evrctl and the built web app, with a SHA256 file per release.

    Full docs
  • No database server neededA single node runs on SQLite and an embedded Pebble history store.db sqlite:… · history pebble:…

    The default when no db or history is set.

    Full docs
  • HTTPS without a proxyevrd can serve the web app over HTTPS itself and redirect plain HTTP, or sit behind any proxy.https_listen :443 · http_listen :80 · web_root

    Port 80 answers Let's Encrypt's http-01 challenge and 443 tls-alpn-01. Behind nginx, Caddy, Traefik or relayd, leave https_listen unset.

    Full docs
  • Upgrades in placeDatabase changes apply at startup. Images are tagged per release; pin one or follow latest.EVRD_VERSION

    Image tags are X.Y.Z, X.Y and latest. With the connection holder, a restart doesn't take anyone off IRC.

    Full docs
  • Restarts only when neededRe-running the OpenBSD installer restarts evrd only if its program changed, and the holder only when it must.

    A release that changes only the web app goes live without a restart.

    Per-node cluster identity comes the same way (EVRD_NODE_ID, EVRD_INTERNAL_URL…).
